## Make a shared decision visible

Change the spacing and watch how the preview responds. The components read shared CSS custom properties, so a single adjustment changes several parts of the interface together.

This is useful when explaining tokens to a teammate: you can see both the benefit of a shared value and the consequences of changing it. A tighter density may help one screen while making another harder to read.

## Separate values from intent

A primitive token names a value, such as a particular shade of blue. A semantic token describes its purpose, such as an action background. Components can reference that purpose while a theme determines which value it uses.

That separation can make theming easier to maintain. It still requires testing: changing a shared color can affect contrast, and changing spacing can affect content fit or target size. Shared values help distribute a decision; they do not guarantee that every result is usable.
